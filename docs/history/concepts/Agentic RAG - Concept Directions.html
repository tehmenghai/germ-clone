01 / THE AGENT LOOP

Seven moves, one loop, until it's learning-grade.

Every question runs this pipeline. Each stage is a collapsible glass-box card in the UI — open it to watch the agent work, collapse it to just read the answer. The whole thing repeats until the evaluation gauge clears threshold.

⟁01
Route
Classifies the question & picks which module(s) and index to search — or sends trivial/chit-chat straight to the LLM, skipping retrieval.

✎02
Rewrite
Expands the raw query into retrieval-friendly form: resolves pronouns, adds synonyms & sub-questions for better recall.
"why does it overfit?" → "causes of overfitting; bias-variance; regularization"
⛁03
Multi-hop Retrieve
Pulls chunks, then follows what it finds — a 2nd hop fetches prerequisites a 1st-pass answer depends on (e.g. bias-variance).
hop 1: 6 chunks · hop 2: +3 (prereq: bias-variance tradeoff)
◈04
ReAct
Reason→Act steps: the agent can call tools — search again, open a notebook, render a formula, or run a quick check — between thoughts.
thought→ need formula · act→ render(LaTeX) · observe→ ok
◎05
Self-Reflect / Correct
Critiques its own draft: every claim grounded? Anything unsupported gets flagged, dropped, or sent back for re-retrieval (CRAG-style).
claim 3 unsupported → drop · gap: no example → re-retrieve
▦06
Evaluate
Scores faithfulness · relevance · completeness on the live gauge. Below threshold? Loop back. Above? Ship it.

✦07
Compose Answer
Writes the final, fully-cited explanation at your chosen difficulty (ELI5 ↔ rigorous), with worked examples & LaTeX.

⌖+
Tools available

↻
The corrective loop: stages 03–06 repeat while any score < threshold. Each pass the rewrite sharpens and retrieval widens — you watch the gauge climb v1 → v2 → v3 until it clears, then stage 07 composes.

The loop is the guarantee. If faithfulness, relevance, or completeness fall below threshold, the agent rewrites its query, retrieves more, and tries again — up to N passes — rather than shipping a weak answer. You watch the gauge climb each pass.

Why does my decision tree overfit, and how do I stop it?
A decision tree overfits when it grows deep enough to memorise noise in the training set rather than the underlying signal — it keeps splitting until each leaf is nearly pure1. That drives training error to zero while test error climbs: the classic high-variance regime of the bias–variance tradeoff2.

To rein it in, constrain capacity: cap max_depth, raise min_samples_leaf, or prune back weak splits. Ensembling (random forests) averages many de-correlated trees to cut variance further3.

The bias–variance tradeoff describes how a model's error decomposes into two competing sources. Bias is error from oversimplified assumptions — a model too rigid to capture the pattern (underfitting)1. Variance is sensitivity to the particular training sample — a model so flexible it fits noise (overfitting)2. Total expected error = bias² + variance + irreducible noise3, so lowering one often raises the other; the goal is the sweet spot that minimises their sum.
⊞ worked example · KNN: small k → low bias / high variance; large k → high bias / low variance. ∑ renders live as LaTeX.

Both penalise large coefficients, but differently. L2 (Ridge) adds the squared magnitude — it shrinks weights smoothly toward zero but rarely to zero, good when most features matter1. L1 (Lasso) adds the absolute magnitude — its diamond constraint drives some weights exactly to zero, doing feature selection2. Use L1 when you expect sparsity; L2 for correlated features; elastic net blends both3.
